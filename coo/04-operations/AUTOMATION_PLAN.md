# 운영 자동화 로드맵

## 현재 상태: 대부분 수동

| 작업 | 현재 | 목표 | 우선순위 |
|---|---|---|---|
| 문의 접수 확인 | 없음 | 자동 이메일 | 🔴 높음 |
| 리드 → 병원 배정 | 수동 | 자동 (스코어 기반) | 🟡 중간 |
| 병원 견적 요청 | 수동 | 자동 발송 | 🟡 중간 |
| 환자 진행 상황 알림 | 없음 | 자동 시퀀스 | 🟡 중간 |
| 일일 리포트 | 없음 | 자동 발송 | 🟢 낮음 |
| 성과 통계 갱신 | 수동 스크립트 | Cron 자동화 | 🟢 낮음 |
| DB 백업 | Supabase 자동 | 추가 외부 백업 | 🟢 낮음 |

## Phase 1: 환자 자동 응답 (가장 시급)

### 구현 계획
1. 문의 접수 → 즉시 확인 이메일 발송
2. 병원 매칭 완료 → 안내 이메일
3. 견적 도착 → 견적 안내 이메일
4. 48시간 무응답 → 리마인더 이메일

### 기술 스택 선택지
- **Resend** (추천): 개발자 친화적, 무료 100건/일
- **SendGrid**: 검증된 서비스, 무료 100건/일
- **AWS SES**: 가장 저렴, 설정 복잡

## Phase 2: 리드 자동 매칭

### 구현 계획
1. 리드 스코어링 (이미 구현: `leadQuality/scoring.ts`)
2. 병원 성과 데이터 (이미 구현: `hospital_performance_stats`)
3. **자동 매칭 로직 추가**: 시술 유형 + 병원 전환율 + 가격대 기반
4. **자동 견적 요청**: 매칭된 병원에 자동 발송

## Phase 3: 모니터링 & 리포팅

1. Sentry 에러 추적
2. UptimeRobot 서비스 모니터링
3. 일일 매트릭스 Slack/이메일 리포트
4. Vercel Cron으로 통계 자동 갱신
